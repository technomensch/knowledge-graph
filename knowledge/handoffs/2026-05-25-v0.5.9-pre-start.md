## Critical Issue: Fallback Logic Missing in Shipped Hook Scripts

**This is the most important thing to fix in v0.5.9 (Task 6b in the plan).**

`scripts/pre-skill-rules-inject.sh` and `scripts/hooks-master.sh` were updated today to reference `~/.kmgraph/plan-rules.md` and `~/.kmgraph/governance-rules.md`. But users who have not split their `rules.md` won't have these files — the hook sections will silently fail to inject.

**Approved fix pattern:**
```bash
KMGRAPH_PLAN_RULES="$HOME/.kmgraph/plan-rules.md"
KMGRAPH_GOVERNANCE_RULES="$HOME/.kmgraph/governance-rules.md"

# Fallback: if split files don't exist, read from rules.md
[ -f "$KMGRAPH_PLAN_RULES" ] || KMGRAPH_PLAN_RULES="$KMGRAPH_RULES"
[ -f "$KMGRAPH_GOVERNANCE_RULES" ] || KMGRAPH_GOVERNANCE_RULES="$KMGRAPH_RULES"
```

This is Task 6b in the v0.5.9 plan. The staleness-check loop in `hooks-master.sh` also needs a `[ -f "$profile_file" ]` guard.

## AMENDMENT: Recall Enforcement Plan (2026-05-25 — Late Session)

An amendment plan was drafted today to extend recall enforcement to all planning contexts. This captures decisions from the multi-platform planning session and feeds into both v0.5.9 and v0.6.0 scope.

**Amendment plan location:** `~/.claude/plans/i-just-realized-that-binary-panda.md`
**Status:** Awaiting user approval before implementation begins.

### Key Decisions from Amendment

1. **Recall HARD BLOCKs in planning must use two queries:**
   - Query 1: Specific topic (e.g., "rules split pattern")
   - Query 2: Architectural domain vocabulary (e.g., "schema evolution hooks")
   - Rationale: Single-query patterns miss contextual rejections stored under domain vocabulary; two queries surface both explicit and implicit precedent.

2. **Recall results priority:** Results take priority but are not a hard veto — model must reason about WHY an approach was rejected before accepting or overriding. Prevents cargo-cult implementation of deprecated patterns.

3. **Rule file locations (authoritative for v0.5.9+):**
   - User-level recall rule: `~/.kmgraph/plan-rules.md` (ENH-016 split already applied)
   - Project-level override: `knowledge/plan-rules.md` (optional, per-project)
   - Canonical rule text: `core/rules-registry/recall-in-planning.md` (new file, Task G in amendment)

4. **Template seeding targets (v0.5.9 scope):**
   - Inject recall rule into both `core/templates/knowledge/templates/project/rules.md` AND user-level template
   - Ensures new projects and new users both inherit the pattern on first install

5. **v0.6.0 setup-platform work (out of v0.5.9 scope):**
   - `commands/setup-platform.md` already exists but is not wired to real implementation
   - Must inject recall rule per platform: Gemini, Cursor, Copilot, MCP-only — all undelivered
   - ENH-017 (remote session rule injection) and ENH-018 (recall vocabulary indexing) need to be created
