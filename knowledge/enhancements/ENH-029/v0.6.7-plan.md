## Task 2: Fix apply order — sort applyList before dispatch loop

**File:** `mcp-server/src/tools/upgrade.ts` — around line 588-604

**Problem:** `applyTemplates()` runs before `applyStarterRelocation()`. Templates deploy `lesson-template.md`, `ADR-template.md`, `session-template.md` to `templates/`. Starter relocation then finds those files already in `templates/` with different content and skips them, leaving live-dir copies in place.

**Root cause:** Execution order is determined by the order of elements in `applyList` (the user/LLM-supplied `apply` array), NOT by switch-case label order. Reordering case labels has zero runtime effect.

**Fix:** Sort `applyList` by a canonical apply order before the `for` loop at line 604.

- [ ] **Step 2.1: Read the apply dispatch block**

Read `upgrade.ts` lines 585-635 to confirm exact variable name (`applyList`) and loop structure.

- [ ] **Step 2.2: Insert applyList sort before the loop**

After the line `const applyList = params.apply ?? [];` (line 588), insert:

```typescript
const APPLY_ORDER = [
  "directories",
  "config",
  "starter-relocation",   // must run BEFORE templates
  "templates",
  "stray-knowledge-dir",
  "platform-split",
  "version-update",
];
const sortedApplyList = [...applyList].sort(
  (a, b) => APPLY_ORDER.indexOf(a) - APPLY_ORDER.indexOf(b)
);
```

Then replace `for (const category of applyList)` (line 604) with `for (const category of sortedApplyList)`.
