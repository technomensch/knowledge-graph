# v0.6.5 — Wire kmg-init → kg_upgrade (Close init ↔ kg_upgrade Drift)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> ⚠️ `commands/` is PROTECTED. Modifications to `commands/` and `commands/kmg-init-shared/` are **explicitly authorized by the user** for this plan. Do not ask for re-confirmation per task.

**Goal:** Make `kg_upgrade` the single source of truth for structural upgrade detection in the `kmg-init` wizard by calling it at the start of the upgrade-inspector module and routing its results into the existing wizard UI.

**Architecture:** Two parallel init commands exist — `commands/kmg-init.md` (project KG) and `commands/kmg-init-personal-kg.md` (personal/user KG) — both call the same shared modules in `commands/kmg-init-shared/`. `commands/kmg-init-shared/kmg-upgrade-inspector.md` gets a new Step 0 that calls `kg_upgrade` (inspect mode, no args), incorporates its items into the `upgrades[]` display, and routes apply for MCP-covered checks through `kg_upgrade apply`. The four overlapping bash detection blocks (directories, templates, starter-relocation, stray-knowledge-dir) are removed. All other sections (b, d, e, f, g, h, i, j, k) are unchanged. `kmg-init.md` and `kmg-init-personal-kg.md` both get stale module path fixes (ADR-053 rename fallout). ENH-022 spec gains a v0.6.5 scope addition and updated checkboxes.

**Tech Stack:** Markdown slash commands (no TypeScript changes). No `npm run build` required.

